Understand the Church-Turing Thesis

The Church-Turing thesis emerged from Turing's 1936 paper "On Computable Numbers, with an Application to the Entscheidungsproblem". In order to understand it, I started reading "The Annotated Turing" by Charles Petzold. From this I learnt that in the early 20th century, mathematicians (Hilbert and Russel were important figures) wanted to axioms for all of mathematics that were:

  1. Independent - You should not be able to derive one axiom from others
  2. Consistent - Contradictory statements should not both be provable.
  3. Complete - All true statements in this formal system can be proven
    • Interestingly, in his PhD thesis, Kurt Gödel proved that first order logic is complete. His later famous incompleteness theorems showed that any formal system powerful enough to do arithmetic could not have both consistency and completeness.
  4. Decidable - For any statement, we must be able to know wether it is provable or not.

So what was the Church-Turing thesis about? It was about that last point - whether mathematics can be decidable. Wheter you can define an algorithm which, for any statement, you can say "yes this is provable" or "this is not provable". This is what is meant by "Entscheidungsproblem", which is German for decision (Entscheidung) problem (problem). The Church-Turing thesis is called such because Alonzo Church also proved, just before Turing did, that the system of axioms used in all of mathematics is not decidable. Because Turing's proof was independently derived, original, and maybe more intuitive, both were given credit solving the Entscheidungsproblem

What is machine learning?
Machine learning is the use of algorithms that can learn or change their behaviour based on data that is provided to them. The end result of providing an algorithm with data is that it has developed a ‘model’ - a representation of the data that it was exposed to.

What is involved in each stage of the ML pipeline?
The ML pipeline is the process followed to build and deploy a model. First, data has to be gathered - this could involve scraping, querying databases, or deploying sensors in the real world to collect information. Then data preparation involves going through the collected data to identify data quality issues, addressing those issues, and building new features out of the data you have (i.e. feature engineering) - this is a discipline in itself and will be covered as a later topic. After this, an algorithm has to be selected, and a model trained - again a whole discipline and will be covered in later topics. Finally, the model has to be deployed in the real world - built into an app or integrated into an API.

What are descriptive and target features?
Features are pieces of data, e.g. the height of a person, temperature at a time of day, etc. Descriptive features are features that will be used when a model is deployed to make a prediction.

What are confounding features?
Confounding features are features that are not not relevant to what the model is trying to predict. Holding on to this data will just slow you down.

What are training, validation, and test sets?
When building a model (‘model training’ step of the ML pipeline), the dataset (constructed during ‘data preparation’) is split into three disjoint sets, namely training, validation, and test set, to train, validate, and test a model. During training, data fed to the algorithm is used to mold and shape the model - it’s the process of narrowing down the space of all possible models to just one. A handful of different models (that use different algorithms) can be trained. In the validation step, the performance of each trained model is assessed to see how they perform on data that was not in the training set. The results of this assessment can be used to filter out models that don’t generalize beyond the training set. After this, testing is where a model is assessed again to ensure it didn’t just perform well on the training and validation sets, and to get a sense of how well it will perform in deployment.

What is supervised, unsupervised, and reinforcement learning?
Supervised learning is when instances have descriptive feature values and target feature values or ‘labels’. The goal is to develop a model that correctly maps descriptive feature values to target feature values. E.g. medical diagnosis based on a common set of health measurements.
Unsupervised learning is when instances only have descriptive feature values. E.g. clustering or dimensionality reduction.
Reinforcement learning algorithms are ones that are able to explore their environment and learn through trial and error. E.g. an agent learns how to navigate by being rewarded for successful navigation.

What does it mean for a model to be underfit or overfit?
Underfitting is when a model is when a machine learning algorithm has not been given sufficient data to develop an accurate model.
Overfitting is when a model is too complex for its domain, and learns the anomalies or peculiarities of the data that it was trained on.

What is the bias variance trade-off in model development?
Bias is indicative of wrong assumptions made by a model. A model with high bias will, on average, make predictions that are far from the true target value. Bias is often a result of underfitting.
Variance in indicative of a model’s sensitivity. A model with high variance will make very different predictions as a result of small changes in descriptive feature values. This is often a result of overfitting.
The trade-off or tension between bias and variance is that reducing one could lead to increasing the other. If you train a model more to avoid bias, you might end up with an overfit or high variance model. The point in training that minimizes bias and variance optimally has to be determined during model development.

What is inductive, restriction, and preference bias in ML algorithms?
The inductive bias of a machine learning algorithm is the set of assumptions that it makes about the world. The restriction bias defines how the models an algorithm develops is restricted, e.g. linear models assume that points lie on a straight line. The preference bias defines how different models are compared or preferred, e.g. the model with smaller errors is selected over others.

What are ill-posed problems?
An ill-posed problem is one where a unique solution cannot be determined using only the information that is available. This applies to machine learning because most ML problems are ill-posed, and multiple models can be developed to solve them.

What is k-fold cross validation?
k-fold cross validation is the process of partitioning a dataset into k equal sized subsets, and running k training experiments where, for each experiment, one data-subset is used as a test set, and the other subsets are used for training and validation. The performance of an algorithm is then measured as the average of the k experiments. This technique is often used when there is little data.

What is the difference between data missing completely at random, at random, and not at random?
Missing completely at random (MCAR) is when there is no link between the missing values and the actual data. E.g. power went out and caused a sensor to stop recording data.
Missing at random (MAR) is when data for a particular feature is missing, not because of the values of that feature, but because of some related (potentially recorded) feature. E.g. historically men are less likely to answer surveys on mental health.
Missing not at random (MNAR) is when there is a direct relationship between the actual value of a feature, and whether or not those values are missing. E.g. severely overweight people may not have a reported weight because it could not be measured.

What is data leakage, test-train contamination, and target leakage?
Data leakage is when information appears in a data or training set that does not reflect the world as it would look when a model is deployed.
Test-train contamination is when information in the test set has influenced the values in the training set. E.g. test set values are used to impute missing values in the training set, thereby contaminating it.
Target leakage is when the training set contains values that aren’t available or set as they are during deployment. E.g. in a time-series context (like administering medicine to patients) a descriptive feature might change after a prediction has been made, and one risks leaking values that arose after a model’s prediction into the data that is used to train it for before the prediction.

What is concept drift?
Concept drift is when the values of a target feature changes over time. E.g. inflation of asset prices would lead to a model trained on old data to be highly biased.

What is sampling bias?
Sampling bias is when the data used to train a model does not accurately reflect the domain that has to be modeled.

3.3 Identifying Data Quality Issues

A data quality issue is loosely defined as anything unusual about the data.

Common data quality issues include:

  • missing values
  • irregular cardinality
  • outliers

data quality issues can be due to:

  • valid data
    • not necessarily correct, take note of issues that may influence the model
    • make a ‘data quality plan’ = Feature + Data Quality Issue + Potential Handling Strategies
  • invalid data
    • errors in generating the dataset, usually with calculating derived features
    • these errors should be addressed
      • regenerate the analytics base table
      • re-create the data quality report
3.3.1 Missing Values

Why might there be missing values?

  • mistakes in the data collection or derivation process
  • some information would only be collected after a certain date
  • people may choose not to provide certain information (e.g. age/gender)

if >= 60% of a feature is missing, it’s best to remove it.

3.3.2 Irregular Cardinality

Cases:

  1. Card = 1: if not due to error, remove
  2. Low card: check if continuous feature should be categorical
  3. Higher than expected: possibly because multiple values are used to represent the same thin, e.g. male, m, M, etc.
  4. High card: not a mistake, but a problem for certain algos; to be noted in data quality plan
3.3.3 Outliers

There are two types of outliers:

  • invalid outliers
    • often due to entry errors
  • valid outliers

Ways of identifying outliers:

  1. ensure that the min/max is within the range you’d expect (e.g. >0 for age)
  2. compare the gap between mean, quartiles, and max/min. large dif -> outlier
  3. Use box plots or histograms to notice outliers

Some ML algos don’t work well with outliers, so this should be noted in the data quality plan.

3.4 Handling Data Quality Issues

3.4.1 Handling Missing Values

Approaches for handling missing values:

  1. Drop the feature with missing values
  • (-) (often needless) loss of data
  1. Derive a binary feature to indicate missing values and discard original feature
  • (+) missingness has relationship to target value
  1. Complete case analysis
  • remove instances with missing values.
  • (-) may remove too many instances or introduce bias
  1. Impute missing values
  • Replaces missing values with plausible estimated values
    • Continuous: media or mean (or a model)
    • Categorical: mode (or a model)
  • (-) risks biasing dataset (avoid imputation if >30% of values are missing)
  • (+) avoids data loss
3.4.2 Handling Outliers

Approaches for handling outliers: 1. Clamping values exceeding upper and lower thresholds to those thresholds - Thresholds can be manually set, or calculated from data. E.g. - quartiles, plus/minus 1.5 times inter-quartile range - 2 standard deviations from the mean (if data is normally distributed)

What is the inductive bias of similarity based learning?
The inductive bias of similarity based learning (SBL) is that instances that have similar descriptive feature values should have similar target feature values. SBL is a form of supervised learning.

How can SBL be applied to classification, regression, and imputation?

What are the core components of a SBL model?
Any similarity based model has to have a set of memorised descriptive-target feature mappings, and a similarity measure or metric defined on the descriptive feature space.

What is the nearest neighbour algorithm?
The nearest neighbour algorithm predicts the target value of a query instance by assigning it the target value of the training instance that is most similar, according to the similarity metric defined on the descriptive features.

import math

class Instance:
    def __init__(self, descriptive, target):
        self.descriptive = descriptive
        self.target = target

    def __str__(self):
        return f"{self.descriptive} -> {self.target}"

def nearest_neighbour_prediction(training, metric, query):
  nn_dist = math.inf
  nn_prediction = None

  for t_inst in training:
    dist = metric(t_inst.descriptive, query.descriptive)
    if dist < nn_dist:
      nn_dist = dist
      nn_prediction = t_inst.target

  return nn_prediction

What is lazy learning?
Lazy learning is when a model delays processing training data until a prediction is needed. The nearest neighbour algorithm is an example of lazy learning because it only uses training data when actual measurements have to be made with the query instance.

How does the k-nearest neighbour algorithm (kNN) work?
The kNN algorithm finds the k training instances that are closest to the query instance, and use them to predict the target value for the query instance.

import math

def k_nearest_neighbour_prediction(training, metric, query, k):
  k_nn = []

  for t_inst in training:
    dist = metric(t_inst.descriptive, query.descriptive)
    if len(k_nn) < k:
      k_nn.append((dist, t_inst))
    else:
      farthest_nn = max(k_nn, key=lambda x : x[0])
